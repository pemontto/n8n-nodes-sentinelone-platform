# Activity output and control layout

The previous activity envelope contained the alert's unified ID, but omitted the name and other current alert context already fetched during scope validation. The result was difficult to identify without another lookup. Adding the full alert by default would make the output larger than necessary; a compact default summary is enough to identify it.

Activity output now starts with `alertId`, `alertName` and `alertExternalId`. The external ID is the detection source's identifier, not an alias for the activity ID or unified alert ID. The committed GraphQL schemas define it as a string. `currentAlertStatus`, `currentAlertSeverity` and `currentAlertAnalystVerdict` come from the existing parent lookup. Recorded changes remain in `changes[]`, and missing summary values remain null. Adding the two query fields does not add an API request.

The editor changes follow n8n's guidance to put optional fields in a collection and bundle dependent controls. Account, Site and Group form one optional Scope selection for alert listing and triggers. Alert Activity's single Occurred operation is hidden; real choices remain visible for Alert. Match Conditions is shown when there are conditions to combine. SDL's tenant/account query boundary and its required account selection remain together because they identify the query target. Required Alert ID inputs remain prominent. [n8n UI design guidance](https://github.com/n8n-io/n8n-docs/blob/main/docs/connect/create-nodes/plan-your-node/node-ui-design.md), [collection controls](https://github.com/n8n-io/n8n-docs/blob/main/docs/connect/create-nodes/build-your-node/reference/node-ui-elements.md)

Scope migration is atomic. Without the new Scope option, saved legacy fields remain effective. With it, its entire selection replaces the legacy scope, including explicitly empty selections. This prevents mixing a new account with stale saved sites or groups. Existing workflow selections must be moved without changing their values, credentials, other options or activation state. Moving the controls alone must not change the effective configuration fingerprint.
